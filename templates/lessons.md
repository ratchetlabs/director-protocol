# Lessons

Running log of corrections → rules that prevent the same mistake. Newest first.

> **Usage rule (binding — CHECKLISTS.md §10).** After ANY correction — by the user, by an
> arbiter, or by your own second look — append an entry here in the fixed shape:
>
> - **Context** — what was being done.
> - **What happened** — the mistake, with the numbers.
> - **Fix** — what was changed.
> - **Rules** — a generalized, TRIGGER-shaped rule that would have PREVENTED the mistake
>   (not a description of the fix).
>
> Then, in the same edit, answer two questions in the entry:
> 1. **Fixture?** Can a construction fixture, static check, or schema assertion express
>    this rule mechanically? If yes, the fixture is the primary artifact — build it and
>    point at it here.
> 2. **What does this retire?** Which existing review step is now redundant with this
>    lesson/fixture? Retire it in the same edit. A ratchet that only adds process
>    reproduces the ceremony-density failure this protocol exists to prevent.
>
> This file starts EMPTY on purpose: the ratchet is the engine, and it earns its
> authority by recording YOUR project's corrections.
